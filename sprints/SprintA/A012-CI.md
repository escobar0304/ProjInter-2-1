## Objetivo

Validar automaticamente cada Pull Request antes de entrar no `main`, para apanhar erros cedo.

## O que foi feito

- Workflow [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml), que corre em cada Pull Request para o `main`, em cada push para o `main` e manualmente (*Run workflow*, no separador *Actions*).
- **Lint de Markdown:** o markdownlint-cli2 verifica todos os ficheiros `.md`, com a configuração em [`.markdownlint-cli2.jsonc`](../../.markdownlint-cli2.jsonc).
- **Links internos:** o remark-validate-links confirma que os links entre ficheiros e para secções (`#titulo`) existem.
- **Schema PostgreSQL:** quando existir `database/schema.sql`, o CI cria uma base de dados PostgreSQL 18 descartável e corre o script, parando ao primeiro erro de SQL. Enquanto o ficheiro não existir, este job é ignorado.

## Decisões

- **Regras de lint tolerantes.** Estão desativadas as regras de comprimento das linhas (MD013), título na primeira linha (MD041), linguagem nos blocos de código (MD040), alinhamento das tabelas (MD060) e HTML no Markdown (MD033). São detalhes de formatação que não afetam o conteúdo. As restantes regras, como os saltos de nível nos títulos ou as listas mal formadas, continuam ativas.
- **Actions fixadas pelo SHA do commit**, e não pela tag, para que uma alteração numa action externa não mude o CI sem passar por um Pull Request.
- **Ferramentas com versão fixa** (markdownlint-cli2 0.24.0, remark-cli 12.0.1 e remark-validate-links 13.1.0), para os resultados não mudarem de uma execução para outra.
- **Permissões mínimas** (`contents: read`) e nenhum segredo no workflow. As credenciais do PostgreSQL são descartáveis e só existem durante o job.
- Os jobs de **backend** (lint e testes em Python) e de **frontend** (build em React) ficam para a Sprint B, quando houver código.

## Como verificar

- No separador *Actions* do GitHub, o workflow **CI** corre em cada Pull Request, com os jobs "Lint de Markdown", "Links internos" e "Schema PostgreSQL".
- Teste de falha: num Pull Request de teste, um `.md` com um salto de nível nos títulos (`#` seguido de `###`) ou com um link para um ficheiro inexistente faz o CI falhar.
- Localmente, na raiz do repositório: `npx markdownlint-cli2@0.24.0`.
